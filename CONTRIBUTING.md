## Начало работы

1. Сделайте **Fork** репозитория на GitHub
2. **Клонируйте** свой форк локально:

```bash
git clone https://github.com/<ваш-логин>/logihub.git
cd logihub
```

3. Создайте **тематическую ветку** для изменений:

```bash
git checkout -b feature/моя-фича
# или
git checkout -b fix/issue-42-ошибка-доступа
```

4. Внесите изменения, выполните сборку и протестируйте
5. Откройте **Pull Request** в `attackuwu/logihub`

## Настройка окружения

### CachyOS / Arch Linux (рекомендуется)

Это основная платформа разработки. На CachyOS гарантируется полная совместимость.

```bash
sudo pacman -S meson ninja gcc pkgconf gtk4

git clone https://github.com/attackuwu/logihub.git
cd logihub
meson setup build --buildtype=debug
meson compile -C build

./build/logihub
```

### Прочие дистрибутивы

> **Примечание:** проект тестируется в первую очередь на CachyOS.  
> На других системах возможны проблемы с версией GTK4 (требуется ≥ 4.10).  
> Если вы успешно собрали и запустили проект на системе, отличной от CachyOS, сообщите об этом в Issue.

| Дистрибутив | Команда установки зависимостей |
|-------------|-------------------------------|
| **Fedora 39+** | `sudo dnf install meson ninja-build gcc pkgconfig gtk4-devel` |
| **Ubuntu 24.04+** | `sudo apt install meson ninja-build build-essential pkg-config libgtk-4-dev` |
| **Debian 12+** | `sudo apt install meson ninja-build build-essential pkg-config libgtk-4-dev` |
| **openSUSE Tumbleweed** | `sudo zypper install meson ninja gcc pkg-config gtk4-devel` |

### Сборка релизного архива

```bash
./package-release.sh
# → release/logihub-1.0-linux-x86_64.tar.gz
```

### Установка udev-правил

Для предоставления доступа к устройству без `pkexec`:

```bash
./install-udev.sh
# затем переподключите мышь
```

## Стиль кода

Проект написан на **C17** с использованием **GTK4**. Придерживайтесь существующих соглашений:

| Правило | Пример |
|---------|--------|
| Отступ: **2 пробела** (без табуляции) | `static void foo(void)` |
| Имена функций: `snake_case` | `device_apply()`, `main_window_init()` |
| Имена типов: `PascalCase` | `LightSettings`, `DeviceResult` |
| Константы и макросы: `UPPER_SNAKE` | `G102_VID`, `HIDPP_SHORT` |
| Новые `.c` / `.h` файлы должны содержать заголовок CC0 | См. шаблон в `src/main.c` |
| Комментарии: русский или английский, но единообразно в рамках одного файла |

### Запрещённые практики

- Необоснованный или попутный рефакторинг
- Переформатирование кода, который вы не изменяли
- Добавление тяжёлых зависимостей без предварительного обсуждения в Issue
- Смешивание табуляции и пробелов

## Виды вкладов

### Добавление поддержки новой мыши

**Наиболее ценный вид вклада.** Если у вас есть мышь Logitech, отсутствующая в списке поддерживаемых, вы можете помочь её добавить.

Порядок действий:

1. Определите **USB VID:PID** вашей мыши:
   ```bash
   lsusb | grep Logitech
   # Пример вывода: Bus 001 Device 003: ID 046d:c092 Logitech G102 LIGHTSYNC
   ```
2. Добавьте новую запись в `udev/99-logitech-hub.rules`:
   ```
   SUBSYSTEM=="hidraw", ATTRS{idVendor}=="046d", ATTRS{idProduct}=="ваш_pid", MODE="0666"
   ```
3. Если мышь не определяется автоматически, добавьте её PID в `src/device.c`
4. Проверьте HID++ feature codes для подсветки (могут отличаться от G102)
5. Обновите таблицу поддерживаемых устройств в README.md и release notes
6. Протестируйте все 4 режима подсветки

> **Примечание:** протокол HID++ является общим для большинства мышей Logitech. Добавление новой модели часто требует только правильного PID и, возможно, других feature-кодов.

### Исправление ошибок

1. Опишите проблему в Issue (или найдите существующий)
2. Минимальный diff — только изменения, необходимые для исправления
3. Укажите номер Issue в PR: `Fixes #N`

### Улучшение интерфейса

Интерфейс находится в `src/main.c` (GTK4 + CSS). Сохраняйте тёмную тему и существующий визуальный стиль карточки устройства.

### Переводы

В настоящее время интерфейс на русском языке. Если вы хотите добавить поддержку других языков, сначала откройте Issue для обсуждения архитектуры i18n (gettext или встроенные строки).

### Документация

Улучшения README, CONTRIBUTING и release notes всегда приветствуются.

## Процесс подачи Pull Request

### Чеклист перед отправкой

- [ ] Код **собирается** без ошибок и предупреждений:
  ```bash
  meson setup build --buildtype=debug && meson compile -C build
  ```
- [ ] Изменения **протестированы** на реальном устройстве (где применимо)
- [ ] Diff **минимален** — только необходимые файлы
- [ ] **Документация** обновлена (README, udev, release notes — при необходимости)
- [ ] Сообщения коммитов **понятны и информативны**
- [ ] В описании PR указаны **дистрибутив** и **модель мыши**, на которых проводилось тестирование

### Формат сообщений коммитов

```
тип: краткое описание

Дополнительные подробности при необходимости.
```

| Тип | Назначение |
|-----|------------|
| `feat` | Новая функция или поддержка устройства |
| `fix` | Исправление ошибки |
| `docs` | Только документация |
| `refactor` | Переработка кода без изменения поведения |
| `chore` | Сборка, скрипты, CI |

**Примеры:**

```
feat: добавлена поддержка G502 X Lightspeed (046d:c099)
fix: обработка EACCES при открытии hidraw без pkexec
docs: обновлена таблица поддерживаемых устройств в README
```

### Процесс ревью

1. Мейнтейнер рассмотрит PR в течение нескольких дней
2. Возможны замечания — внесите правки и выполните force-push в ту же ветку
3. После слияния ваше имя будет добавлено в [CONTRIBUTORS.md](CONTRIBUTORS.md)

## Сообщения об ошибках

Хороший Issue содержит максимум информации. **Обязательно укажите дистрибутив и модель мыши.**

```markdown
**Дистрибутив:** CachyOS, ядро 7.0.10
**Модель мыши:** Logitech G102 LIGHTSYNC
**VID:PID:** 046d:c092
**Версия LogiHub:** 1.1 (или `git describe`)

**Шаги для воспроизведения:**
1. Запустить `./logihub`
2. Выбрать режим «Дыхание»
3. ...

**Ожидаемый результат:**
Подсветка плавно пульсирует выбранным цветом.

**Фактический результат:**
Подсветка не изменяется. Вывод в консоли: `[logitech-hub] ошибка команды: -1`

**Лог (stderr):**
```
[logitech-hub] Device: /dev/hidraw3 (046d:c092)
[logitech-hub] HID++ version: 4.0
[logitech-hub] ошибка команды: -1
```
```
